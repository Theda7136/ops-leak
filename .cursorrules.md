# OpsLeak - Cursor Project Rules & Guidelines

## 🚀 Vision del Proyecto
OpsLeak es una plataforma de inteligencia operacional para empresas con equipos en campo, servicios o logística. Transforma reportes informales de trabajo diario (textos, audios transcritos, notas) en análisis en tiempo real mediante la API de Grok (xAI), detectando desviaciones de presupuesto y cuellos de botella antes de que ocurran.

## 🛠️ Stack Tecnológico Mandatorio
- **Framework:** Next.js 14+ (App Router, Server Actions, TypeScript strict mode).
- **Styling:** Tailwind CSS + `shadcn/ui` + Lucide Icons.
- **Base de Datos & ORM:** PostgreSQL + Prisma ORM.
- **AI Engine:** API de Grok (xAI) a través del SDK de OpenAI (configurando base_url a `https://api.x.ai/v1`).
- **State/Form:** React Hook Form + Zod para validaciones.

## 🎨 Principios de Diseño UI/UX
- Dashboard con estética **Enterprise / B2B SaaS moderno** (inspirado en Vercel, Linear o Stripe).
- Uso de paleta de colores limpia: fondos oscuros o grises Slate, banderas de estado claras (Verde = Normal, Amarillo = Riesgo Moderado, Rojo = Riesgo Crítico / Cuello de Botella).
- Visualización clara de métricas clave (KPIs): Presupuesto Ejecutado vs. Estimado, Horas Muertas Detectadas, Alertas Críticas Activas.

## 🤖 Guía de Integración con Grok API (xAI)
- Cuando trabajes en `lib/grok.ts` o controladores de IA, usa la estructura de chat de la API de Grok.
- Configura siempre respuestas estructuradas (JSON) para extraer datos de reportes desestructurados:
  - `summary`: Resumen de 1 frase de lo ocurrido en la jornada.
  - `hoursLost`: Número estimado de horas operativas perdidas.
  - `costImpact`: Estimación de sobrecosto (si aplica).
  - `severity`: "LOW" | "MEDIUM" | "CRITICAL".
  - `bottleneckType`: "MATERIAL_DELAY" | "EQUIPMENT_FAILURE" | "LABOR_IDLE" | "WEATHER" | "OTHER".
  - `actionRecommended`: Acción concreta e inmediata para el director operativo.

## 📐 Reglas de Código
- Mantén los Server Components por defecto; usa `'use client'` solo cuando sea necesario interacción en el cliente (formularios, hooks, estados).
- Separa la lógica de negocio de los componentes UI.
- No uses `any` en TypeScript. Define interfaces claras en `@/types`.
- Todas las llamadas a API de Grok y base de datos deben estar envueltas en bloques `try/catch` con manejo explícito de errores.
